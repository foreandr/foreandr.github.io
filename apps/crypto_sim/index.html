How Symmetric Cryptography Works

Alice and Bob share a single secret key K — they must exchange it securely beforehand. Every message is encrypted with K and can only be read by someone who knows K. The Man-in-the-Middle intercepts everything that passes through the network but can only see ciphertext. If they don't have K, they cannot decrypt the message — unless they break the cipher by brute force. Click any node at any time to see exactly what that party knows.

How Asymmetric (Public Key) Cryptography Works

Each party generates a key pair: a public key shared with everyone and a private key kept secret. Alice encrypts a message using Bob's public key — only Bob's private key can decrypt it. The Man-in-the-Middle can see all public keys and all ciphertext, but cannot decrypt without the recipient's private key. A real MITM attack requires substituting their own public key — watch what happens if they try. Click any node to see the full knowledge state of that party.

How Hybrid Encryption Works (e.g. TLS/HTTPS)

Asymmetric encryption is expensive for large messages. Hybrid schemes use asymmetric crypto only to securely exchange a short session key, then switch to symmetric encryption for the actual data. Alice picks a random session key, encrypts it with Bob's public key, and sends it. Bob decrypts with his private key to get the session key. From then on both use the session key like symmetric encryption. The Man-in-the-Middle sees the encrypted session key but can't unwrap it without Bob's private key.
